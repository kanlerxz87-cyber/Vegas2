Suggestions for review

These suggestions are for your review only. Nothing here has been implemented. Choose the ones you want (for example S1, S4, S6) and we will implement only those.

How to choose: reply with the IDs you want (for example S1, S4, S6). Only those are implemented. Nothing on this page changes the data.
S1Decision-makingProposed

Add a weighted scoring table for hotels

Score each hotel on price, Michelin count within reach, room fit and travel time. Weights are set by you. Shows the top pick clearly.

Benefit
Turns the ranking into one decision you can check.
Trade-off
Needs your weights, and the price and transit columns must be filled first.
S2PricingProposed

Build a price log for each hotel (manual check on set days)

Record official rates for Feb 15–18 and Feb 15–22, 2027 at a fixed time each week, with a link and timestamp. The 'cheapest time to book' is then read from the log.

Benefit
The only honest way to find the cheapest booking time, since no official history is available.
Trade-off
Needs a weekly check; a few months of data is needed before conclusions.
S3Travel timeProposed

Verify transit times with RTC Southern Nevada routes

For each hotel, record the bus route, boarding stop, and scheduled time to each Michelin restaurant and activity. Only official RTC schedule data is used.

Benefit
Enables the '1 hour by bus' test the brief asks for.
Trade-off
Schedules vary by day and time; results are estimates from published data.
S4MichelinProposed

Pull per-restaurant price ranges from Michelin Guide pages

Open each of the 24 restaurant pages on the Michelin Guide site and record price ranges, cuisine and hours exactly as shown.

Benefit
Gives the 2-adult cost range the brief asks for, from the source Michelin uses.
Trade-off
guide.michelin.com could not be retrieved in this session; needs a manual or retried pass.
S5CoverageProposed

Add Downtown hotels so the Esther's Kitchen and SoulBelly cluster is covered

Two of the Michelin restaurants sit on S. Main St. Downtown hotels would let that cluster be scored like the Strip.

Benefit
Fair comparison across the whole Michelin list.
Trade-off
Adds more hotels to verify.
S6ActivitiesProposed

Choose the activities list first, then re-run the travel-time check

Pick the activities (for example Hoover Dam, Red Rock, Valley of Fire, Neon Museum, or others). Then add distance and drive or bus time from each hotel.

Benefit
Makes the 1-hour test concrete.
Trade-off
Needs your answer to Q1.
S7PresentationProposed

Add a 'last verified' date to every row

Show the date each value was checked, so old data is easy to spot.

Benefit
Makes the verification standard visible on each row.
Trade-off
More columns; mobile cards get longer.
S8QualityProposed

Add an automated link check on each push (GitHub Actions)

Run the site checker on every push to catch broken links and empty required sources before the site publishes.

Benefit
Protects against broken links after future edits.
Trade-off
Adds a small workflow file to the repo.
S9Decision-makingProposed

Add a 'deal breakers' list (bathroom, bed, budget cap, distance cap)

Hotels that fail a must-have are moved to a separate section instead of being ranked.

Benefit
Stops the ranking from including hotels you cannot accept.
Trade-off
Needs your input on Q4 and Q7.
