Repository review

Every finding was produced by a command run against the checked-out repository or the GitHub API on 2026-11-27, after rebasing onto main at 76b22b8. Line numbers refer to that commit. Findings that could no longer be reproduced were removed rather than carried forward.

Verdict. Re-audited after the root dashboard was replaced by the integration session (PR #22). The four line-level defects this reviewer originally logged against the old root index.html — conflicting hotel prices, an unsourced '~15–20 minute' travel claim, a wrong MICHELIN reveal date and a '3–4 nights' span for a 3-night window — no longer exist in the tree, so they have been retired rather than repeated. What remains are structural issues that still hold today.

R-01 high Two independent build systems publish to the same Pages URL The GitHub Pages API reports build_type 'legacy' with source branch 'main' and path '/', while .github/workflows/pages.yml line 27 uploads 'path: docs' as an artifact deployment. Both mechanisms target the same site, so which content a visitor receives depends on deployment ordering rather than on a single source of truth.

Impact: A stale legacy build can silently override a newer artifact deploy (or the reverse), and neither pipeline guards the other. Any future move to a custom domain or branch change has two places to update.
Fix: Disable the legacy branch source in repository settings and keep only the Actions deployment in pages.yml.		 Repository settings + .github/workflows/pages.yml:27
R-02 high CI does not validate the pages it deploys The three validators in .github/workflows (pages-check.yml:23, validate.yml:29, validate-field-notes.yml:27) assert only against docs/session-059c3126, docs/session-b29fc34e and docs/session-2e5e3452. Root *.html and docs/*.html — the pages a visitor actually lands on — are rebuilt and compared by nothing.

Impact: A regression on the landing page or any category page can merge with every check green. The session pages are the best-tested artifacts in the repository; the front door is the least-tested.
Fix: Add one job that rebuilds the root site from its generator and fails on `git diff --exit-code`, the same pattern already used for the three session directories.		 .github/workflows/*.yml
R-03 medium Published session archive still asserts a superseded star count docs/session-36cc5108/flagged.html contains the phrase 'three starred'. The current 2026 MICHELIN Guide Southwest selection has four starred Las Vegas restaurants (two-star Joël Robuchon plus one-star é, Guy Savoy and L'Atelier de Joël Robuchon).

Impact: An archived page contradicts the live selection on a fact a traveller is likely to plan around. Because the archive is published and indexable, the error is reachable without any warning that it is historical.
Fix: Either correct the archived page or add a dated banner marking it superseded, and point readers to the current MICHELIN page.		 docs/session-36cc5108/flagged.html
R-04 medium No LICENSE file `ls LICENSE*` returns nothing at the repository root. No licence text appears in README.md either.

Impact: Without an explicit grant, default copyright applies: the content is technically all-rights-reserved and third parties cannot safely reuse it. It also leaves the provenance of the aggregated research ambiguous.
Fix: Add a LICENSE file (or a short 'all rights reserved' statement) so the terms are explicit.		 repository root
R-05 medium Root site and docs/ subsites do not link to each other A crawl of the 7 root *.html pages finds 0 hrefs into docs/, and a crawl of docs/*.html finds 0 hrefs back up to the root. The two halves of the published site are reachable only by typing a URL.

Impact: Five session subsites and the canonical dashboard form two disconnected islands. A visitor who lands deep in docs/ has no route back to the main planner.
Fix: Add a single persistent 'back to planner' link in each subsite header, and a 'research archive' link on the root.		 *.html, docs/*.html
R-06 low Historical snapshots live inside the deployed tree docs/session-legacy-root/ holds a full copy of a previous root dashboard (activities, flagged-for-review, hotels, index, questions, restaurants, suggestions) plus a main-0d3e73e snapshot. Because pages.yml uploads all of docs/, these archives are published and indexable.

Impact: Superseded pages stay publicly reachable and compete with current content in search results, while also inflating every deployment artifact.
Fix: Move archives outside docs/ (or exclude them in the workflow) and keep one clearly-labelled snapshot per merge.		 docs/session-legacy-root/
R-07 low Root pages are very long single-line HTML index.html lines 41–46 each contain an entire table section on one physical line (the hotel and restaurant blocks are single lines several thousand characters long).

Impact: Line-anchored code review and git blame are effectively impossible for those regions; any edit rewrites a whole line. It also makes the file hostile to line-based diff review.
Fix: Emit one element per line from the generator so diffs and blame stay readable.		 index.html:41-46
